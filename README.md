# Daily_Note

**Daily_Note** — веб-приложение электронного дневника для хранения личных записей и организации повседневной информации в одном месте.

Приложение помогает вести дневник, структурировать записи по блокнотам и папкам, прикреплять материалы (фото, документы, рисунки) и планировать важные события.

## О проекте

Личная информация часто хранится в разных местах: бумажных блокнотах, заметках телефона, отдельных файлах и календарях. Из-за этого бывает сложно быстро найти нужную запись или вспомнить о запланированном событии.

**Daily_Note** объединяет инструменты для ведения личных записей и планирования в одном веб-приложении.

### Цель проекта

Разработать удобное веб-приложение, которое позволяет пользователю хранить, систематизировать и находить личную информацию, а также получать напоминания о важных событиях.

## Основные возможности

В проекте реализованы следующие возможности:

- регистрация и авторизация пользователей (с подтверждением email);
- создание и редактирование личных записей;
- организация записей с помощью вложенных дневников (папок);
- работа с вложениями к записям (фото, видео, документы);
- **встроенный графический редактор** — рисование прямо в записи (работает мышью и пальцем на смартфоне);
- календарное представление записей и событий;
- создание напоминаний (как отдельных, так и привязанных к записям);
- автоматическая отправка уведомлений (через Celery);
- поиск и фильтрация записей по тегам, датам и заголовку;
- **полностью адаптивный интерфейс** (десктоп и смартфон);

## Бизнес-ценность

Daily_Note помогает пользователю организовать личную информацию и сократить количество ручных действий.

- **Экономия времени.** Записи хранятся структурированно (вложенные папки), поиск по тегам и датам работает мгновенно.
- **Централизация информации.** Заметки и связанные с ними материалы (фото, документы, рисунки) находятся в одном пространстве.
- **Планирование.** Календарь и напоминания помогают не забывать о важных датах и событиях.
- **Автоматизация.** Уведомления отправляются автоматически (через Celery и Redis), без участия пользователя.
- **Удобство.** Пользователю не нужно переключаться между блокнотом, календарём и файловым хранилищем.
- **Доступность.** Приложение работает в браузере на любом устройстве (ПК, планшет, смартфон).

## Установка и запуск (локально)

### 1. Клонирование репозитория

```bash
git clone https://github.com/dementievaolga082489/Daily_Note.git
cd Daily_Note

### 2. Установка зависимостей

Убедитесь, что Poetry установлен, затем выполните в корневой папке проекта:

```bash
poetry install
```

Poetry установит зависимости, описанные в `pyproject.toml`, и будет использовать `poetry.lock`.

### 3. Настройка переменных окружения

Создайте файл `.env` в соответствии с настройками проекта. Не добавляйте в Git реальные пароли, секретные ключи и токены.

Пример возможных параметров:

```env
SECRET_KEY=your-secret-key
DEBUG=True

DATABASE_NAME=your_database
DATABASE_USER=your_user
DATABASE_PASSWORD=your_password
DATABASE_HOST=localhost
DATABASE_PORT=5432

CELERY_BROKER_URL=redis://localhost:6379/0
CELERY_RESULT_BACKEND=redis://localhost:6379/0

EMAIL_HOST_USER=your-email@example.com
EMAIL_HOST_PASSWORD=your-email-password
```

Названия переменных должны соответствовать `settings.py`.

### 4. Применение миграций

```bash
poetry run python manage.py migrate
```

### 5. Создание администратора

```bash
poetry run python manage.py createsuperuser
```

Следуйте инструкциям в терминале.

### 6. Запуск локального сервера

```bash
poetry run python manage.py runserver
```

После запуска приложение будет доступно по адресу:

http://127.0.0.1:8000/

> Команды `poetry run ...` выполняют программу внутри виртуального окружения Poetry. Поэтому отдельно активировать виртуальное окружение обычно не требуется.

## Фоновые задачи

Если в конфигурации проекта используются Celery и Redis, сначала запустите Redis. Затем откройте отдельные терминалы и запустите worker и планировщик Celery Beat.

Запуск worker:

```bash
poetry run celery -A config worker -l info
```

Запуск Celery Beat:

```bash
poetry run celery -A config beat -l info
```

> На Windows для некоторых конфигураций Celery может понадобиться запуск worker с параметром `-P solo`.

## Развёртывание на сервере (Docker & CI/CD)

Проект настроен на автоматическое развёртывание через **GitHub Actions**. Каждый пуш в ветку `main` (или `develop`) запускает пайплайн:

1. **Тесты** (`python manage.py test`).
2. **Линтеры** (`flake8`, `black`, `isort`).
3. **Сборка Docker-образа** и публикация в Docker Hub (`olga0824/daily-note:latest`).
4. **Деплой на сервер по SSH**:
   - логин в Docker Hub;
   - `docker compose pull`;
   - `docker compose up -d --remove-orphans`;
   - `docker image prune -f`.

### Что нужно для развёртывания на сервере

- Установленные **Docker** и **Docker Compose**.
- Папка `DEPLOY_DIR` (например, `/home/user1/daily-note`) с файлами:
  - `docker-compose.yml`;
  - `.env` (с продакшн-настройками: `DEBUG=False`, `ALLOWED_HOSTS`, пароли и т.д.);
  - `nginx/nginx.conf`.
- Секреты в GitHub (`Settings → Secrets and variables → Actions`):
  - `DOCKER_HUB_USERNAME`, `DOCKER_HUB_ACCESS_TOKEN`;
  - `SECRET_KEY`;
  - `SERVER_IP`, `SSH_USER`, `SSH_KEY`, `DEPLOY_DIR`.

### Состав `docker-compose.yml`

| Сервис | Назначение |
|---|---|
| `db` | PostgreSQL |
| `redis` | Брокер для Celery |
| `migrate` | Применение миграций и сбор статики |
| `web` | Gunicorn + Django |
| `celery` | Worker фоновых задач |
| `celery-beat` | Планировщик |
| `nginx` | Reverse-proxy и раздача статики |
